## 3. 登壇者別サマリ

### 3.1 みずほ証券 杉谷氏

セッション内容：エンタープライズ企業でモダン化に取り組む際の留意事項

- Frontier AIの対策に言及
- 脆弱性対応を継続するため、自動化が必要
- GitHubの活用に言及
- オフショアを利用している場合、従来よりコストが安いため大幅なコスト削減にはつながりにくい
- 金融庁からの要請など、金融機関として必要な対応コストが存在する
- エンタープライズ企業におけるモダン化では、技術面だけでなく、金融庁の要請等の規制対応に対する必要な対応コストであることを主張すると事業会社には刺さりやすい等

### 3.2 LiNKX株式会社 水野氏

セッション内容：仕様駆動によるAI駆動開発／レガシーモダナイゼーションでの検証と型化

- SDD（Spec Driven Development：仕様駆動開発）を紹介
- AI駆動開発を、仕様、タスク、ワークフロー、レビューなどを組み合わせて進める
- ワークフローとレビューを担当するエージェントを活用
- コンテキストとフィードバックループを重視
- 社内プロジェクトでは、API GatewayやClaude Code Sonnetを活用
- レビューコストをどのように削減するかが課題
- AI開発に関する3つの原則を提示
  1. AI活用＝自動化
  2. AIに絶対はない
  3. チームの実力がAIの実力

### 3.3 ULSコンサルティング 漆間氏

セッション内容：レガシー刷新、Devinにどこまで任せられるか

Devin前提でおきることとして、次の問題が発生する。

- 現行仕様が分からない
- 物量が多くて終わらない
- レビューが追いつかない
- 移行後も現行システムと同じ動作になることを証明できない
- 作業量を見積もれない

これらに対し、次のように対応する。

1. 現行コードをリバースエンジニアリングし、仕様を起こす  
　 ※但し、業務仕様までは読み取れない
2. 移行処理をパターン化し、並列に実行する
3. 一次レビューは全てDevinに流す
4. 現行動作保証は、変換後のコードでテストを作って担保する

### 3.4 東京システムハウス 比毛氏

セッション内容：AI駆動開発／私たちはCOBOLとどう向き合うか

- 脱COBOLや、AIによるCOBOLモダナイゼーションが注目されている
- COBOLシステムは規模が大きく、全体を一度に扱うことが難しい
- 対応には「分担」と「知識」が重要
- 生成AIだけで既存システムの仕様書を作り上げることは難しい
- ソースコードの解読品質や429エラーが発生し変換処理が途中で中断すること等の課題がある
- 用語集がない場合、コードや業務用語を誤って変換する可能性がある
  - 例：本来は「本支店コード」である用語がHST-CDと誤変換された
- コード変換処理においては確率的に変換処理を行うAIでは対応が難しい
- COBOLを維持する選択肢と、Javaへ移行する選択肢の双方を検討する必要がある
- AIに十分な情報を与えれば、汎用AIでもCOBOLコードを生成できる
- MCPを活用し、COBOL保守をAIネイティブな開発へ移行する構想を紹介
- モダナイゼーションの方式として、リテイン、リホスト、リライト（頻度大）、リビルドに言及

### 3.5 株式会社SHIFT 竹村氏

セッション内容：AI活用によるレガシーモダナイゼーションとプロジェクトマネジメント

- リビルドでは、リバースエンジニアリングとフォワードエンジニアリングを実施
- リライトでは、フレームワークを移行
- AI活用には次の課題がある
  - AIを全面的に信用できない
  - 出力の再現性が低い
  - モジュール全体がコンテキストを読み込めない
  - ナレッジが蓄積されることで、AIが意図しない処理を行う場合がある
- AIによる変換結果を全面的に信用せず、現行システムとの現新比較を実施する
- リライトすべき要素を事前に洗い出したうえでAIを適用する
